# ADR-0003: 全量记忆与 memory-space 分层，日终整理

- 状态：Accepted
- 日期：2026-11-13
- 相关：ADR-0001、ADR-0002

## 背景

“把会话内容整理进全量记忆”需要区分两种记忆：

1. **原始档案**：当天说过什么、发生过什么，要求完整、可追溯、不被摘要覆盖；
2. **可检索记忆**：从当天内容提炼出来的事实、偏好、承诺、黑话，要求短、可召回、可修改。

如果只保留 memory-space，会丢掉原文；如果只保留原文，模型难以高效召回。

同时，整理必须满足：

- 不阻塞新一天；
- 幂等，重复执行不重复写入；
- 失败可重试；
- 不依赖 DSH 一直在线到换日时刻。

## 决策

### 1. 两层记忆

| 层 | 位置 | 内容 | 写入方式 |
| --- | --- | --- | --- |
| 全量档案 | `~/.dsh/onefish-core/archive/` | 当天会话原文/日摘要/冷索引 | append-only |
| memory-space | `~/.dsh/onefish-core/memory-v2/space/` | core / active / knowledge 条目 | 提炼写入 |

全量档案是“历史事实来源”；memory-space 是“可召回的记忆索引”。两者不能互相替代。

### 2. 日终整理流程

`consolidate(day)` 的顺序固定为：

```text
读取 DSH 当天会话历史
  ↓
写全量档案（原文或按消息聚合的日志）
  ↓
生成日摘要（规则优先，LLM 可选）
  ↓
从摘要/原文提炼 memory-space 条目
  ↓
标记 consolidated
```

硬性规则：

- **先落档案，再做提炼**；提炼失败不影响档案；
- 同一天重复执行必须幂等；
- 失败保留 `pending`，下一次启动/定时重试；
- 新一天创建不能等待旧一天整理完成；
- 整理使用逻辑日 `dayKey`，而不是自然日 00:00。

### 3. 幂等键

每次整理记录：

```json
{
  "day": "2026-11-13",
  "sessionId": "session-...",
  "sourceHash": "sha256(...)",
  "archivePath": "...",
  "status": "consolidated",
  "attempts": 1
}
```

- 已存在且 `sourceHash` 未变化 → 跳过；
- `sourceHash` 变化 → 允许追加/修正，不覆盖旧档案；
- 同一天多次失败不重复写部分档案。

### 4. 提炼边界

- 全量档案：允许保留完整原文；
- memory-space：只写“值得长期保留”的内容，避免把整段对话塞进去；
- `core` 只放身份/边界/长期承诺；
- `active` 放偏好、近况、项目事实、待办；
- `knowledge` 放黑话、梗、表情语义；
- 提炼结果必须可追溯：记录来源 day / sessionId / 消息范围。

### 5. 整理触发

- 换日后第一次 `ensureToday()`：先 seal 昨天，再异步/后台 consolidation；
- DSH 启动时：检查未完成的 consolidation，补跑；
- 定时检查：低频即可，不要求整点；
- 不要求 DSH 在 04:00 在线。

## 后果

### 正面

- 原文不丢，可追溯；
- memory-space 保持短小、可召回；
- 整理失败不影响新一天；
- 后续档案检索、日摘要、冷索引都有明确落点。

### 负面 / 风险

- 档案会持续增长，需要按日/周/月做冷索引和清理策略；
- LLM 提炼有成本和不确定性，必须先落原文；
- 隐私内容进入档案，需要访问边界和备份策略；
- 需要防重复写入的幂等实现。

## 备选方案

### A. 只写 memory-space（否决）

丢失原文，无法回溯“当时到底说了什么”。

### B. 只写全量档案（否决）

模型召回效率低，每次都要读长文。

### C. 每条消息实时提炼（否决）

成本高、噪声大、容易把临时对话写成长期记忆。

### D. 整理失败就阻塞新一天（否决）

会让用户无法开始新一天对话。

## 验收标准

- 同一天重复 `consolidate` 不产生重复档案/重复条目；
- 提炼失败时档案仍存在，状态为 `pending`/`failed` 可重试；
- 新一天创建不等待旧一天整理；
- 每条 memory-space 条目可追溯到来源 day/session；
- 全量档案可按天检索；
- 逻辑日切换使用 04:00 口径，而不是 00:00。
